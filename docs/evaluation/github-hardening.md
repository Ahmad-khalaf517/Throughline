First, the ADR generator included its own ItemVersion and Architecture version but omitted the upstream Requirement ItemVersions, Requirements source ArtifactVersion, and stored decision rationale. This worktree now reads the stored `semantic_dependency` edges and the Architecture version's recorded Requirements generation context through their owning modules. It puts exact bound IDs/revisions and decision text in each ADR, and the same IDs in `lineage.json`. A missing legacy Requirements context is represented as `null` plus an empty list, never inferred from the current Requirements version. Second, marker-based reconciliation previously marked a repo completed after a lost create response even though no README/ADR/lineage files had been written. Reconciliation now verifies the ownership marker first, then creates only missing generated files; it never overwrites existing files or completes while a file lookup/write has an ambiguous failure. Third, an approved Architecture B could previously reuse Architecture A's ambiguous same-name operation because its request hash contained only name and mode. The operations owner now rejects a GitHub same-key request with a different source version before provider calls. Retry uses the stored operation's original Architecture version and context, even if it was later superseded; a superseded definitive failure cannot start a new create. Focused fake-provider cases cover historical Requirement binding, lost create/file responses, and A-to-B supersession, including no B provider call, no mixed files, exact A ref provenance, and drift after B.
